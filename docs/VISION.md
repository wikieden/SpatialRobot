## 一句话定位

**SpatialRobot 是一套工程落地级的"外置空间海马体"——把 RGB-D 感知融合成一份持久、可查询、带 `#id` 引用的 3D 场景图记忆，挂载到任意 dual-system 机器人大脑的 S2（慢推理 VLM）上，让今天结构性缺失跨帧空间记忆的具身大脑获得"它记得房间里有什么、在哪、什么关系"的能力。**

我们不做第四个 VLA、不做大脑大模型、不做本体——我们做**所有 S2 都能挂载、中立、可商用的结构化空间记忆与查询服务**。

> **一句话定位的诚实边界（吸收工程批判）**："持久、可查询"指的是**存储层**：`.smem` 单文件跨重启存活、可增量更新、可被 `query()` 精确检索。它**不等于**"无限大场景一次性全进 Reasoner 上下文"——后者受 token 预算约束（见 §2.3 截断限制）。卖点是"记忆不丢"+"能查到"，不是"一次塞得下"。

## 1. 问题陈述：为何"所有 S2 都缺持久空间状态"

调研得出的核心格局判断（执行摘要 1–2、第 3 章范式、6.1 wedge）是本项目存在的理由：

**1.1 技术范式已从端到端 VLA 收敛到分层 dual-system，但这一收敛把记忆问题暴露得更彻底。** [已验证·调研 confirmed]
2024–2025 头部公司（Figure Helix、Physical Intelligence π0.5/Hi Robot、NVIDIA GR00T N1、Google DeepMind Gemini Robotics-ER）已趋同到 **S2（7B 级 VLM，约 7–9 Hz，规划）+ S1（约 80M policy，约 200 Hz，控制）** 的双系统结构。

> 表述纪律：调研中"双系统是工业**事实标准**""PsiBot 最早提出双系统"两项分别被标记为**证据偏强**与 **refuted**。本文一律采用更保守的"头部公司趋同"措辞，不写"事实标准"、不写任何首创归属。

**1.2 无论端到端 VLA 还是 dual-system 的 S2，都结构性地没有持久、可查询的跨帧空间状态。** [已验证·调研 confirmed] 这是报告反复确认的硬事实：OpenVLA / π0 / Helix / GR00T / Gemini-ER 均为单帧或短上下文，**无显式场景记忆、无跨帧持久状态**（第 3 章范式表"劣势"列）。机器人转个身，刚才看到的东西就"忘了"。

**1.3 头部公司在事实上需要它，但都没把它做成独立可复用的层（6.1 证据链）：**

这里必须区分**外部一手证据**与**内部分析**（吸收战略批判 CRITICAL-1，避免自循环论证）：

*外部一手信号（公开可查，非本项目自证）：*
- Physical Intelligence 到 **π0.7 才补 history vision encoder（MEM）**——头部团队用产品行动承认了记忆缺口；
- 1X 在其公开材料明确提"需要 **memory context** 处理 drift / partial observability"；
- 智源 BAAI 的 **RoboOS 把"跨机器人空间记忆共享"直接写进架构文档**；
- 学术侧 3DLLM-Mem 在 3DMem-Bench 上**困难任务 32.1% vs 基线约 5%**（论文实测，已确认）——这是"记忆层带来真实可测增益"的**外部第三方数据**。

*仍属间接推断（标注为内部分析，不作终审依据）：*
- Field AI 无地图导航的定位 / 重规划痛点"指向"持久空间状态——是我们的解读，非其声明；[内部分析]
- Dyna 的在职持续学习"需要"持久环境知识——同上；[内部分析]
- 银河通用零售货架状态追踪"等价于"我们的能力——同上。[内部分析]

> **关闭 wedge 自循环（OQ-3 的一半）**：上述"内部分析"项不能作为 wedge 成立的证明，只能作为"值得做客户访谈验证"的线索。wedge 的真正外部支撑只有三条：π0.7 的产品行动、RoboOS 的架构文档、3DLLM-Mem 的第三方数据。**对外传达 wedge 时只引用这三条。**

**1.4 学术已是清晰范式，但几乎无人把它工程化为可装、可嵌、可商用的独立组件。** [已验证·调研 confirmed] ConceptGraphs、Hydra/Clio、HOV-SG、Embodied-RAG、3DLLM-Mem、RoboMemory 都是这一范式的实现，但都是研究代码或重 C++/ROS 栈。

> 表述纪律：报告将"3DLLM-Mem 比基线高 6 倍"标记为 **refuted**——论文主口径是绝对 **+16.5 个百分点**，"6 倍"仅对应 hard 子集。本文只引用绝对值与 hard 子集的 32.1% vs 约 5%，不写"6 倍"。

**结论：缺失的不是更强的 VLA，而是一个所有 S2 都能挂载的外置持久空间记忆层。这就是 SpatialRobot 的技术生态位。** 但"技术生态位成立" ≠ "商业生态位成立"——后者取决于 OQ-1/OQ-2/OQ-3，见 §6。

## 2. 我们做什么 / 明确不做什么

### 2.1 我们做什么（站在"空间记忆极"）

报告第 3 章把赛道归纳为三个**正交互补**的极：
- **动作生成极**（端到端 VLA → dual-system，两代主线）；
- **数据 / 想象极**（world model，learned simulator + 合成数据）；
- **持久状态 / 记忆极**（空间记忆 / 3D 场景图）。

SpatialRobot 明确站在第三极，做三件事：

1. **Memory（`spatialmem`，记忆核）**——numpy-only 的 `.smem` SQLite 3D 场景图：融合（fuse）→ 持久化（persist）→ 查询（query）。它是整个系统**唯一的有状态对象**，是海马体。
2. **Perception（`spatialmem-perception`，眼睛）**——RGB-D → 世界系 `Detection`；相机→世界几何 lift，CLIP 编码（`[clip]` extra 后才引入 torch）。
3. **Brain（`spatialmem-brain`，大脑接缝）**——`Brain` 认知循环 + `Reasoner` + `CosmosReasonVerbalizer`，对接**任意 OpenAI 兼容 `/v1/chat/completions`** 的 S2。

三层通过 core 暴露的 **`PerceptionAdapter` / `Verbalizer` / `Reasoner` 三个 Protocol** 作为 BYO 接缝。系统的闭环接口已是雏形：`Brain.ask()` 经 `serialize(format="prompt")` 产出 token 高效、带 `#id` 引用的**层级场景图**喂给 Reasoner，返回 **`Answer(text, cited_node_ids)`**。这正是"VLM planner + 结构化空间上下文"范式的工程实现。

### 2.2 明确不做什么（6.2 normative）

- **不做端到端 VLA / 不做大脑大模型。** 那是 Physical Intelligence / Skild / Generalist / RoboBrain / 千寻 / 自变量的红海，正面竞争必败。
- **不做本体。** 那是宇树 / 智元 / 傅利叶 / 逐际的资本密集赛道。
- **不做 SLAM。** 世界系位姿来自上游（KISS-ICP/MIT、cuVSLAM、ARKit、仿真 ground truth）；**绝不链接 ORB-SLAM3（GPLv3 传染）进发行包**。
- **不做 world model 本身，但做它的结构化先验提供方**（见 §3）。
- **不做"云优先"。** 本地优先、可嵌入、BYO-LLM；托管层是后续便利，**但是否产生收入是开放问题**（见 §6 OQ-2，吸收商业批判：不能既排斥托管护城河又不给替代粘性）。

### 2.3 [已验证·工程限制] 上下文截断：`Brain.ask()` 当前是全图截断，不是子图召回

这是吸收工程批判 **CRITICAL-1** 后必须写进 vision 的硬限制，**直接关系到"持久跨帧空间状态"卖点在大场景下的真实性**。

**代码事实（已核读）：**
- `brain.py:63`：`context = self._mem.serialize(format="prompt", max_tokens=self._budget)`，默认 `max_tokens=1500`；
- `serialize.py:81–82`：节点"most-recent-first"发出，超预算的整段子树丢弃，附 `… (N more omitted)` 标记（非静默，这点是好的）；
- `Brain.ask()` **不先 `query()` 过滤**，而是把整图按时间倒序塞进预算。

**后果：** 一旦节点数超预算，**记忆里有但进不了 Reasoner 上下文的，恰恰是较老的节点**——与"它记得房间里有什么"的核心卖点在大场景下直接矛盾。此时 `Answer.cited_node_ids` 的召回率指标是虚假数字（被引用的只可能是进了上下文的那部分）。

**结论与承诺：**
- 本 vision 明确声明此为 v0 限制，**不对"全图一次性入上下文"做任何承诺**；
- P1 工程任务必须把**"先 `query()` 过滤相关子图再 serialize"**（检索式上下文，而非时间截断）列为正式条目（见 §8 OQ-6）；
- P1 评测集**必须显式覆盖"超预算场景"**，分别报告"全图截断"与"query 子图"两种策略下的召回率，禁止只报小场景数字。

### 2.4 [已验证·工程限制] `cited_node_ids` 是尽力提取，非强保证

吸收工程批判 **HIGH-4**。**代码事实：** `reason.py:18` 用 `_ID_RE = re.compile(r"#(\d+)")` 提取引用；`_PROMPT` 仅含一句 soft instruction `"Cite node ids as [#id]"`。任何 Reasoner 输出格式漂移（`node_3`、`[id:3]`、中文括号）都会导致 `cited_node_ids=[]` 且**静默无错**。对 8B 级 VLM，这条 soft 约束的遵从率本身就是未知数。

**结论与承诺：**
- vision 明确声明 **`cited_node_ids` 是"尽力提取"，不是格式强保证**——"可定位、可审计"是**目标**而非**当前既成事实**；
- P1 评测集分两层：**(a) 格式遵从率**（Reasoner 是否按 `#id` 输出）+ **(b) 内容正确率**（被引用的 id 是否真的相关）；
- P2/P3 路线把 **structured output（JSON mode / function call）替代正则提取**列为明确工程任务（见 §8 OQ-7）。

### 2.5 [已验证·架构边界] 跨机器人"实时共享" vs "离线 merge"

吸收工程批判 **CRITICAL-2** 与战略批判 **HIGH-2**。**代码事实：** `brain.py:8–9` 注释明言"v0 is single-threaded; serialize all access (the core store is one sqlite connection)"；`SpatialMemory.merge()`（`__init__.py:633`）是 **session-replay 式离线合并**，不是实时并发同步。SQLite 单写锁在多机器人并发写时会立即成瓶颈。

**结论（必须在引用 RoboOS"跨机器人实时共享"时同步声明）：**
- **已实现**：跨 episode / 跨机器人的**离线 merge**（一台机器人的 `.smem` 回放进另一份记忆）；
- **未实现**：**实时多机器人并发写**——这需要独立的服务层 / 并发控制 / 冲突解决，是 P3 及以后的工作，当前架构不支撑；
- 因此 §4 引用 RoboOS 作为"需求信号"时，只能说"我们与之在**离线共享**语义上重叠"，**不得**暗示我们当前能做实时并发共享。

## 3. 与 dual-system（S1/S2）及 world model 的关系

### 3.1 与 dual-system 的关系：做 S2 的外挂记忆

```
        ┌─────────────── dual-system 机器人大脑 ───────────────┐
        │                                                      │
RGB-D ─►│  S2 (VLM, ~7-9Hz, 规划)  ◄──注入结构化空间上下文──┐  │──► S1 (policy, ~200Hz)
        │         │                                        │  │      │
        └─────────┼────────────────────────────────────────┼──┘      ▼
                  │  serialize(format="prompt")             │      执行器/本体
                  ▼  带 #id 的层级场景图（受 token 预算约束）│      (不在范围内)
        ┌──────────────── SpatialRobot ───────────────┐    │
        │ perception → memory(.smem) ── query/answer ──┘    │ Answer.cited_node_ids
        └──────────────────────────────────────────────────┘ 回指可定位节点（尽力提取）
```

- **S2 = brain 层对接的外部 Reasoner**（Cosmos-Reason2 / RoboBrain / Gemini-ER / π0.5 等任意 OpenAI 兼容模型）；
- **S1 = 下游控制器**，不在本项目范围内（可对接 LeRobot 5 个官方 VLA：Pi0Fast / Pi0.5 / GR00T N1.5 / SmolVLA / XVLA 作为下游执行器，已确认）；
- **memory 层正好填补"所有这些系统共同缺失的跨帧持久空间状态"**（执行摘要 2）。

我们对 S2 是**中立、可挂载**的：因为接口是 OpenAI 兼容 `/v1/chat/completions` + 协议接缝，同一套记忆层可同时服务中美双方任意 Reasoner（2.3 共同空白）。

> **中立性的双刃边界（吸收商业批判 6、战略批判 HIGH-1）**：中立=技术上谁都能挂，但也意味着**全栈自研厂商（PI / Figure / Helix）没有动机采用外置中立层**——记忆能力正是它们的差异化壁垒。中立性只对**不自研 S2 的纯执行器厂商 / 开源大脑团队**有真实价值。目标客户必须据此拆分，见 §6.1。

### 3.2 与 world model 的关系：互补而非竞争（执行摘要 3、6.2）

报告明确判定：**world model 与空间记忆是互补的第三极，不是替代关系。**
- World model（Cosmos 3、1X WM、Wayve GAIA-1、Covariant RFM-1、自变量 WUM、V-JEPA 2）做的是**像素级 imagination / 合成数据 / 前向预测**，定位是 learned simulator + 合成数据源；
- SpatialRobot 做的是**结构化、显式、可查询的 3D 对象关系记忆**。

两者结合的价值组合（非替代）：
1. 用 world model 生成合成 RGB-D 扩充 perception 训练集；
2. 用 `.smem` 场景图为 imagination rollout 提供**物体位置 / 关系先验，降低搜索空间**。

> 表述纪律：报告将"Cosmos 3 30 秒动作条件预测""Genie 3 2026-01 订阅开放"标记为 **uncertain（一手来源未证）**。本文不依赖这些具体数字定位，仅用其"统一单系统 world model 已确认"的方向性事实。

## 4. 差异化 wedge 与护城河

### 4.1 Wedge（6.1，证据分级后判定"技术上成立、商业上待验证"）

证据链三段（区分外部证据与内部分析后，见 §1.3 的纪律）：
1. 端到端 VLA 与 dual-system S2 **结构性地无持久跨帧空间状态**——[已验证·调研 confirmed]；
2. 头部公司在事实上需要它——**外部证据**只有 π0.7 补 MEM、RoboOS 架构、3DLLM-Mem 数据三条；其余为 [内部分析]；
3. 学术已成范式但**几乎没有人把它做成独立、可装、可商用、numpy-only 的工程组件**——[已验证·调研 confirmed]。

> **wedge 性质的诚实重述**：调研判定 wedge 成立属 **[内部分析]**，不是外部独立确认。对外传达时必须说："技术空白已被三条外部信号佐证；商业付费意愿尚未验证（OQ-1）；护城河可持续性取决于 OQ-3。"

本仓库的工程选择恰好把这套学术能力做成"可嵌入任意 S2 的外置海马体"：
- **numpy-only core**（CLAUDE.md 明令的契约）→ 可装在任何环境，包括边缘端（部署矩阵见 §4.2）；
- **`.smem` 单文件 SQLite + sqlite-vec ANN**（重 backend 后有线性/keyword fallback）→ 重启可存活、可增量更新、零基础设施依赖；
- **`PerceptionAdapter` / `Verbalizer` / `Reasoner` 三协议接缝** → BYO，不锁定上游感知 / 下游模型；
- **`#id` 可引用序列化 + `Answer.cited_node_ids`** → 朝"可定位、可审计"的方向走（当前是尽力提取，见 §2.4）；
- **fuse-before-persist 不变量** → 工程正确性保证（新增 mutator 必先 `_flush_pending()`）。

### 4.2 [新增] 部署配置矩阵：分级可装性

吸收工程批判 **HIGH-5**——"numpy-only 可装边缘端"是核心卖点，但必须澄清它与 perception 包的 torch 依赖的边界，否则本体厂嵌入式团队会预期错位。

| 配置 | 安装 | 依赖 | 算力 / VRAM | 适用 | 端到端能力 |
|---|---|---|---|---|---|
| **core-only** | `pip install spatialmem` | numpy（无 torch、无 CUDA） | CPU、可跑 MCU 级以上 | 边缘端 / 嵌入式 / 接收上游 `Detection` | 融合 + 持久化 + 查询（keyword/linear fallback）；**无视觉前端** |
| **+perception** | `+ [clip]` extra | torch + open-clip + (SAM2/GDINO) | GPU（CLIP 推理） | 有 GPU 的机上 / 边缘盒子 | RGB-D → 场景图（含语义编码） |
| **+brain** | `+ spatialmem-brain` | 仅 stdlib（LLM 远程） | 取决于 S2 部署位置 | 任意（S2 可在云 / 远端 vLLM） | 记忆 + 推理闭环 |
| **full stack** | 全部 + 本地 S2 | torch + CUDA + 本地 vLLM/NIM | 高（如 Cosmos-Reason2-8B 需 RTX PRO 6000 级） | 工作站 / 研发 | 全闭环本地运行 |

**P1 验收必须包含**：(a) **无 GPU 纯 numpy fallback 路径的端到端冒烟测试**（core-only 配置，BYO `Detection` → 查询）；(b) 同时验证 +perception 配置的 GPU 路径。两条都过，"分级可装"才是可信卖点。

### 4.3 护城河（按可防御性排序）+ 结构性可持续性分析

护城河不在单点技术（学术界已有同类范式），而在**工程组件化 + 接口标准 + 评测基准的复合**：

1. **接口标准护城河（最强，但尚未建立）**：争取让 `#id` 可引用 prompt 序列化协议 + `.smem` 持久化格式被一个开源大脑（RoboBrain / InternRobotics）或本体厂**作为默认记忆层采用**。一旦成为"具身记忆标准接口"，迁移成本即护城河。
2. **评测基准护城河（无人占据的空白）**：空间记忆查询正确性的评测**目前无人占据**。我们自建"查询正确性 + `cited_node_ids` 召回率（含格式遵从率）+ 跨 episode 持久性 + decay/forget 正确性"评测集（参照 Embodied-RAG 的 Embodied-Experiences、3DLLM-Mem 的 3DMem-Bench），既证明价值主张，又设立行业标尺。
3. **工程成熟度护城河**：把研究代码做成生产级、network-free 测试、numpy-only 可移植的 SDK，本身是竞品（学术原型）不愿做、本体厂没空做的脏活。
4. **中立性护城河（双刃，需配粘性机制）**：见 §4.4。

**[OQ-3] 为什么本体厂 / 大脑厂不自己花 3 个月内化这个能力？**（吸收商业批判 3、战略批判 CRITICAL-2）

证伪威胁是真实的：π0→π0.5→π0.7 不足一年，RoboBrain 加一个 scene graph 模块的工程成本极低。若护城河只靠"他们没空做"，护城河寿命 = 他们腾出手的时间。我们提出两条**候选结构性理由**，但诚实标注其成色：

- **(a) 组织不兼容性 [内部分析，候选最强]**：内化记忆与"中立跨机器人共享"在组织上天然冲突——宇树不会把自家 `.smem` schema 公开让智元受益；PI 不会把记忆格式开放给 Figure。一个**中立第三方**才能提供"跨厂商互操作"的记忆标准。这是结构性的，不是时间性的。**但前提是"跨厂商互操作"真的有需求**——这本身依赖 OQ-1。
- **(b) 持续维护成本 [较弱]**：工程维护是持续投入而非一次性。这条对资源充足的大厂说服力有限。

**诚实结论**：在 OQ-1（付费方）与 OQ-5（RoboOS 是否自带）关闭前，理由 (a) 仍是**赌注**而非定论。**若最终找不到比 (a) 更硬的结构性理由，本 wedge 应被明确标注为"时间窗口赌注"**——即我们赌的是"在头部内化之前，先把接口标准与评测基准做成既成事实"。这是诚实的定性，不是失败的定性，但必须写明。

### 4.4 [新增·吸收商业批判 6 + OQ-8] 中立性的粘性机制

中立=没有任何客户有强粘性，任何人 fork 后即可走人。向量数据库（Pinecone/Weaviate）也主打中立，但靠**托管 + API + 企业 SLA** 产生收入与粘性——而我们当前排斥托管护城河。必须明确至少一条粘性来源并优先建设：

| 候选粘性 | 机制 | 强度 | 决策 |
|---|---|---|---|
| **`.smem` 格式迁移成本** | 数据一旦以 `.smem` 沉淀，迁出有成本 | 中（格式开放时弱） | 主选之一：靠"格式成为事实标准"放大 |
| **评测基准锁定** | 我们定义"空间记忆正确性如何测量" → benchmark 话语权 | 中高（与护城河 2 一致） | **主选**：谁定义测量方式，谁有标准话语权 |
| **跨机器人持久化数据网络效应** | 多机器人共享同一记忆 → 数据越多越有用 | 高（但依赖实时共享，§2.5 未实现） | 长期赌注，P3 后 |

**决策**：P1–P2 优先建设**评测基准锁定**（与护城河 2 合一，是当前最现实的粘性）；`.smem` 格式标准化作为 P3 接口标准护城河的载体；网络效应是 P3 后的远期选项。**放弃"纯中立无粘性"的天真定位。**

## 5. 北极星指标与首选目标场景

### 5.1 北极星指标（加"质量门"，吸收战略批判 HIGH-3）

**北极星：被 N 个独立的外部 S2 / 本体 / 开源大脑作为挂载式空间记忆层实际采用、且满足质量门的数量。**

仅"接口调通 demo"无法区分真实价值与技术好奇——研究团队接个演示很容易，但不等于生态位锁定，更不等于付费意愿。**合格挂载必须同时满足三条质量门：**
1. **可测提升**：在我们的任务评测集上有可测的长程任务表现提升（不是"跑起来了"）；
2. **持续维护**：集成持续维护 **≥ 2 个月**无断开（证明不是一次性演示）；
3. **对外公开引用**：有论文 / 博客 / 公开代码库引用（证明对方愿意公开背书）。

三条缺一不计入北极星。支撑性指标：
- **正确性**：评测集上的查询正确性、`cited_node_ids` 格式遵从率 + 内容正确率、跨 episode 持久性、decay/forget 正确性；
- **效率**：序列化 token 成本、查询延迟、**大场景 `commit()` 延迟**（见 §8 性能门控）；
- **持久性**：跨重启 / 跨 episode / 跨机器人（离线 merge）的记忆保真度。

### 5.2 首选目标场景（加时序标注，吸收商业批判 5）

**优先选"多班次 / 长时连续作业"场景——这些场景下持久空间记忆是刚需而非锦上添花：**
- 多班次仓储（货物 / 货架状态跨班次追踪）；
- 长时连续作业人形（"长时连续运行"这一**场景类型**，非任何具体厂商的连续时长声称）；
- 零售货架状态（货架状态追踪是教科书级用例）。

> **执行鸿沟的时序纪律（吸收商业批判 5、战略批判 HIGH-1）**：§5.2 的工业场景是**P3 才进入的商业验证方向**，不是 6–12 个月内可交付的工业 PoC。明确分期：
> - **P1–P2 的目标"客户"= 开源大脑 / 本体集成团队**（技术验证，不是工业销售）；
> - **P3 才进入工业场景的商业验证**（需真实机器人集成、工业级可靠性、IT 采购流程）。
> 任何读者不应把 §5.2 误读为近期商业承诺。

> 表述纪律：报告将"优必选 Walker S2 7×24h""Dyna 24h 99%+""Figure Helix 完整 8 小时自主轮班"中部分声称标记为 **uncertain / 误导措辞**。本文仅把这些作为**场景类型**举例，**不引用任何具体连续运行时长作为既成事实**。

## 6. [新增章节] 商业化与 GTM：付费方、许可、Open Core

本章专门关闭商业批判暴露的三个 P0 缺口（OQ-1/OQ-2/OQ-3）。在这三条关闭前，所有技术路线都是建立在假设上的。

### 6.1 付费方 ICP：用 2×2 矩阵锁定首个原型客户（OQ-1）

候选付费方的采购决策链完全不同：

| | **采购能力强** | **采购能力弱** |
|---|---|---|
| **付费意愿高** | （理想 ICP，待证实存在） | 早期研究团队（愿试，无预算） |
| **付费意愿低** | 本体厂（宇树/智元/傅利叶）：自研倾向强，更可能白嫖开源后 fork；系统集成商：有预算但技术栈保守，迁移成本是障碍 | 企业终端用户：买"机器人解决方案"，不买底层 SDK |

**结论与决策：**
- **首个原型客户画像（假设性 ICP，待 P3 访谈证实）**：不自研 S2、但需要长时 / 多班次空间记忆的**纯执行器本体厂或开源大脑团队**——他们没有"自研记忆=削弱护城河"的顾虑（区别于 PI/Figure），且有真实的长程任务需求。
- **[OQ-1 关闭判据]**：P3 必须用 1–2 次真实客户访谈，把上述假设性 ICP 收敛为"愿为某产品形态付费的具体客户原型"。**在 OQ-1 关闭前，不投入重资源做商业化 / 托管。**
- **诚实标注**：当前**没有任何已验证的付费方**——这是本项目最大的商业不确定性。

### 6.2 开源许可 + Open Core 分界线 + 首个商业形态（OQ-2）

当前完全空白。**本 vision 给出待决策的框架（具体值是 OQ-2 的关闭物）：**

- **(a) 发行许可证 [待决策]**：候选——core 用宽松许可（Apache-2.0，最大化采用，符合"靠采用建生态位"）；若需防 free rider，考虑对**托管 / 企业功能**用商业许可（双许可）。**默认倾向：core 宽松、企业层另议。**
- **(b) Open Core 分界线 [待决策]**：候选"仅企业版"功能——跨机器人**实时**并发持久化（§2.5 未实现，天然适合做企业层）、多租户 `.smem`、审计日志 / 合规导出、企业 SLA 支持。**Community 版包含**：core 记忆 + 查询 + 离线 merge + BYO 接缝。
- **(c) 首个商业产品形态 [待决策]**：候选——① SDK license fee；② 托管 API（注意：调研定位"托管层不是护城河"，但**托管可作收入来源，二者不矛盾**——吸收商业批判 2）；③ 上门 PoC 咨询。**默认倾向：P1–P2 不卖；P3 从"PoC 咨询 + 企业层 license"起步。**

**[OQ-2 关闭判据]**：确定 (a) 发行许可证 + (b) 至少 1 个"仅企业版"功能清单 + (c) 首个商业形态。三者落地前，投资人不会认真对待商业叙事。

### 6.3 GTM 路径：从"发布评测集"到"被采用"的机制（吸收商业批判 4）

P2→P3 的"发布评测集 → 被默认采用"跳跃缺少说服机制。补齐为**双层验收**（也写进 §8 P3 里程碑）：

- **(a) 技术采用激励**：明确对方获得什么——节省 N 个工程月的"融合+去重+持久化+序列化"重复造轮子工作（这正是单包 vision 的核心叙事："每个具身团队都在重建同样的管道"）；
- **(b) 商业承诺**：被采用 ≠ 拿走开源后消失。P3"被默认采用"拆成两条独立验收：**技术采用**（对方 import/fork 了）+ **商业承诺**（有 license 协议或付费 PoC）。fork 后是否仍依赖我们 → 取决于 §4.4 的粘性机制（评测基准 + 格式标准）。

### 6.4 [OQ-2 关联] 企业就绪 vs 开发者友好的路线冲突（吸收商业批判 7）

"本地优先、BYO-LLM"对开发者友好，但工业客户 IT 部门要 SLA / 托管选项 / 安全合规 / 技术支持——对企业买家是摩擦而非卖点。**决策（与 §5.2 时序一致）：**
- **P1–P2 明确不做企业销售**——目标是开发者 / 开源团队，"本地优先 BYO-LLM"是正确定位；
- **P3 起增设"企业就绪路径"**（托管选项、支持合同、数据隔离）作为 Open Core 企业层（§6.2），且仅在 OQ-1 关闭后启动。

## 7. 最大长期风险及应对

### 7.1 头号风险：新一代 S2 内化记忆能力 + 明确的临界条件（吸收战略批判 CRITICAL-2，OQ-4）

报告把这一项列为 **wedge 的最大长期风险**：Cosmos 3 / RoboBrain 2.5 等新一代 S2 是否会内化记忆能力——**信号已现：π0.7 已开始内化 MEM（history vision encoder）。** PI 的迭代速度意味着 π1.0 / RoboBrain 3.x 在 2026 年底**有较大概率内化"30 分钟会话级空间状态"**。防御性叙事（"打可审计差异化"）不足以应对，必须给出**明确的失效临界点**：

**[OQ-4·内化临界点定义]** 当某个外部 S2 同时具备以下**全部**能力时，本项目在"该 S2 服务的场景"中 wedge 失效：
1. 跨 episode **持久化**（不只是单会话上下文窗口）；
2. **多机器人共享**（不只是单模型私有记忆）；
3. **可定位 / 可审计**的记忆引用（不只是隐式 latent）。

基于此临界点划分场景：

| 场景 | 内化能否覆盖 | 定性 |
|---|---|---|
| 30 分钟单 episode 单机器人空间状态 | 内化大概率覆盖（受上下文窗口扩展驱动） | **脆弱场景**——不应作为主战场 |
| 跨班次 / 跨天 / 长时持久（超单 episode） | 内化受上下文窗口与单 episode 限制 | **安全场景**（暂时）——主战场 |
| 跨机器人共享（哪怕离线 merge） | 与单模型私有记忆组织上冲突（§4.3 理由 a） | **安全场景**——结构性差异 |
| 可审计 / 可定位（监管 / 合规需求） | 隐式记忆天然做不到 | **安全场景**——但需求规模待验证 |

**应对策略：**
1. **持续监测（必做）**：每季度核读 Cosmos / RoboBrain / π 系列更新，对照上述三条临界条件打分。
2. **主战场只放"安全场景"**：把资源集中在跨班次 / 跨机器人 / 可审计这三类内化天然弱区，主动放弃"单 episode 短期记忆"这一脆弱场景。
3. **赌接口标准与评测基准**（见 §7.3 对类比的修正）。

### 7.2 次级风险：被国内"一脑多形"开源栈自带场景图覆盖（OQ-5，吸收工程批判 6 + 战略批判 HIGH-2）

报告明示：**RoboOS / InternRobotics 是否已自带场景图记忆，决定我们是"互补"还是"被覆盖"。** 当前路线图存在逻辑矛盾——§1.3 把 RoboOS 当需求佐证，P2 又把"RoboOS 集成"当验收目标，但"被覆盖"结论可能在 P2 第一周就出现。

**应对（先探后定，调研前置为门控）：**
- 把 **RoboOS / InternRobotics 场景图能力边界调研提前到 P1 末尾**，作为 **"P2 前置门控 spike"（约一周）**；
- 在 spike 出结论前，§1.3 对 RoboOS 的引用**降级为"待验证市场信号"**，不作为需求佐证；
- spike 结论决定 P2 目标：**若 RoboOS 已自带完整场景图** → P2 转向"更轻量 / numpy-only 可移植 / 跨栈中立"的差异化或**轻量替代定位**；**若未自带** → P2 坐实"互补集成"。
- **不预设 P2 集成目标**，避免"被覆盖"使整个 P2 验收标准失效。

### 7.3 战略风险：接口标准护城河的类比修正（吸收战略批判 MEDIUM-1）

原稿用"向量数据库接口价值上升"类比论证接口标准护城河——**此类比失效**：向量数据库真实护城河是托管运维，接口已高度同质化（pgvector 直接进 Postgres）。修正后的论证：

- **改用"评测基准定义权"**：谁定义"空间记忆正确性如何测量"，谁有标准话语权（与 §4.3 护城河 2、§4.4 粘性机制一致）；
- **改用"`.smem` 格式跨机器人互操作性"**：跨厂商场景下，统一格式的迁移成本是真实壁垒（与 §4.3 理由 a 一致）。
- 这两条比向量数据库类比更可防御。

### 7.4 商业风险：付费意愿未验证

见 §6.1（OQ-1）。列为 P3 显式里程碑；验证前不投重资源做托管 / 商业化；先用开源采用度（北极星，含质量门）建生态位。

### 7.5 战略纪律：不被营销数字带节奏

## 8. 分阶段路线（P1 / P2 / P3）

依据调研 6.3 并吸收工程批判（性能门控、协议 v2、评测可行性）与商业批判（双层验收）落到三阶段。

### P1 · 地基（0–3 月）：坐实 memory core 与 BYO 接缝

> **范围纪律（吸收工程批判 7）**：P1 同时交付"首个 PerceptionAdapter + 双 Reasoner 后端 + 标注 QA 评测集"对单人团队过度乐观。因此 P1 评测**只做自动化、确定性的部分**；人工标注语义正确率推到 P2；P1 出口判据**不挂虚假的"查询正确率 Y%"**。

| 里程碑 | 验收标准 |
|---|---|
| 首个 `PerceptionAdapter` 具体实现（ConceptGraphs 路线：SAM 2 + GroundingDINO + OpenCLIP，全 Apache/MIT，behind `[perception]` extra） | RGB-D 序列 → `.smem` 场景图端到端跑通；core 仍 numpy-only（pyright clean，无 torch import 入核） |
| **PerceptionAdapter Protocol v2 设计**（吸收工程批判 HIGH-3） | 现协议仅 `process_frame()`，无生命周期接口；v2 至少加 `__enter__`/`__exit__`（或 `close()`/`flush()`），管理有状态 encoder（CLIP 模型加载）的生命周期 |
| **检索式上下文（先 query 过滤子图再 serialize）**（吸收工程批判 CRITICAL-1，OQ-6） | `Brain.ask()` 不再全图截断；超预算场景下召回相关子图。评测覆盖"超预算场景"，分别报告全图截断 vs query 子图两种策略召回率 |
| 坐实双 Reasoner 后端 | Cosmos-Reason2（本地 RTX PRO 6000，OpenAI 兼容 `/v1`）与 RoboBrain 两条后端均能驱动 `Brain.ask()` 返回带 `cited_node_ids` 的 `Answer` |
| **自建空间记忆评测集 v0（自动化、确定性）** | 用已有 `SyntheticScene` 生成确定性场景 + 脚本自动生成 QA 对；只做 **recall@k + `cited_node_ids` 格式遵从率**（不做人工语义标注）；覆盖跨 episode 持久性 + decay/forget 正确性；产出第一份 baseline 数字 |
| **性能门控**（吸收工程批判 HIGH-3） | 除现有"100 obs / 30ms"外，新增 **"1000 obs / 100 nodes 场景下 `commit()` 延迟"** 上限作为验收门 |
| **部署矩阵冒烟**（吸收工程批判 HIGH-5） | (a) 无 GPU 纯 numpy core-only 路径端到端冒烟（BYO `Detection` → 查询）；(b) +perception GPU 路径冒烟。两条都过 |
| **[P2 前置 spike] RoboOS / InternRobotics 场景图能力调研**（吸收战略批判 HIGH-2，OQ-5） | P1 末一周完成；产出调研文档，结论决定 P2 集成方向（互补 / 轻量替代）。在此之前 §1.3 RoboOS 引用降级为"待验证信号" |
| 核心质量门 | core 覆盖率 ≥ 75%；测试全程 network-free（ScriptedReasoner / HashEncoder）；ruff + pyright 通过 |

**P1 出口判据**：能用一句**可复现**的话证明 wedge 不是 PPT——"内存里有 X 个物体、跨重启存活、在确定性合成场景上 recall@k = R、`cited_node_ids` 格式遵从率 = F、1000 obs `commit()` 延迟 < T、纯 numpy 路径冒烟通过"。**注意：是 recall@k 与格式遵从率（可自动测），不是人工标注的语义正确率。**

### P2 · 集成验证（3–6 月）：在真实本体 + 开源生态上端到端

| 里程碑 | 验收标准 |
|---|---|
| 1–2 个开源友好国内本体上的端到端 demo | 优先傅利叶 N1（完全开源）、逐际 FluxVLA（MIT）；零售货架是教科书用例。产出可复现 demo + 视频 |
| 接入 LeRobot 生态 | LeRobotDataset v3.0 作为喂 `PerceptionAdapter` 的标准数据源；下游对接其官方 VLA（Pi0Fast/Pi0.5/GR00T N1.5/SmolVLA/XVLA 之一）作 S1 |
| **对接外置 S2（方向由 P1 spike 决定）** | 若 RoboOS 未自带场景图 → 坐实"互补集成"；若已自带 → 转"轻量 / numpy-only 可移植 / 跨栈中立"差异化或轻量替代。**不预设结论** |
| 评测对外 + 人工语义标注 | 评测集对外发布，邀请 1–2 个外部团队复现；**补做 P1 推迟的人工语义正确率标注** |
| **`cited_node_ids` 两层评测 + structured output 探索**（吸收工程批判 HIGH-4，OQ-7） | 分别报告格式遵从率 + 内容正确率；探索 JSON mode / function call 替代正则提取 |

**P2 出口判据**：至少 1 个外部团队在真实或半真实本体上跑通"挂载 SpatialRobot 后 S2 长程任务表现**可测提升**"（不是"跑起来了"）。

### P3 · 生态位锁定（6–12 月）：做成"具身记忆标准接口" + 首个商业验证

| 里程碑 | 验收标准 |
|---|---|
| 发布稳定序列化协议 | `#id` 可引用 prompt 格式版本化、向后兼容承诺；`.smem` schema 稳定版；structured output 作为 `cited_node_ids` 的强保证路径落地 |
| 跨 episode / 跨机器人持久化 + 生命周期 | decay / consolidate / forget 生命周期对外稳定；跨机器人**离线 merge** demo（实时并发共享明确标为 P3 后） |
| **被默认采用（双层验收）**（吸收商业批判 4） | **(a) 技术采用**：某开源大脑 / 本体厂 import/fork 为默认记忆层；**(b) 商业承诺**：有 license 协议或付费 PoC（不是拿走开源后消失） |
| **商业基线（关闭 OQ-1/OQ-2）** | 完成 1–2 次真实客户访谈，收敛假设性 ICP 为具体付费客户原型；确定发行许可证 + Open Core 分界线 + 首个商业形态；启动企业就绪路径（托管 / 支持 / 数据隔离） |

**P3 出口判据**：北极星指标 ≥ 1 个外部大脑/本体把 SpatialRobot 作为**默认**（非可选）记忆层**且满足质量门三条**（可测提升 + ≥2 月维护 + 公开引用），同时 OQ-1 有可信的付费客户原型。

## 9. 许可红线与工程红线（6.4，硬约束，分级管理）

吸收战略批判 **MEDIUM-2**：许可红线（不可逆法律风险）与工程红线（可控技术债）失效后果不同，**不应混用同一优先级**。拆为两类，各带例外升级路径。

### 9.1 许可红线（法律合规约束 · 不得违反 · 无例外路径）

**发行包绝对不可链接以下传染 / 非商业许可组件：**

| 红线 | 原因 | 替代 |
|---|---|---|
| **ORB-SLAM3** | **GPLv3 传染**，对商业不友好 | 位姿用 **KISS-ICP（MIT）** / KISS-SLAM |
| **AgiBot World / 部分 RoboCasa 数据集** | **CC BY-NC-SA 非商业**，商业产品**不可用** | 商业用 OXE（CC BY 4.0）/ DROID（宽松）；非商业仅研究 |
| **OpenVLA / 任何 LLaMA-2 衍生权重** | **LLaMA-2 7 亿 MAU 条款**（已确认） | 优选 LLaMA-3.2 / Qwen 系骨干（如 OpenVLA-mini） |
| **GR00T N1 / N1.5 权重** | **NVIDIA 非商业许可，禁商用** | 商业用 **N1.7（Apache-2.0）** 或 Cosmos Open Model License |

> **例外升级路径**：无。许可红线无例外——任何引入传染 / 非商业组件进发行包的提议一律拒绝。仅"非商业研究分支"可在隔离、不发行的前提下使用 NC 资源，且不得回流主线。

### 9.2 工程红线（架构完整性约束 · 变更需 RFC + 负责人批准）

- core 保持 **numpy-only**——给 `SpatialMem/` 加 torch/LLM import 即破契约；
- **fuse-before-persist 不变量**——新增任何 mutator 必先 `_flush_pending()`；
- 测试 **network-free**——用 `ScriptedReasoner` / `HashEncoder`，绝不在测试中触达真实 LLM 或下载模型。

> **例外升级路径**：工程红线是可控技术债，变更需走 **RFC 流程 + 架构负责人批准**（区别于许可红线的"无例外"）。例如若未来证明 core 必须引入某轻量可选依赖，需 RFC 论证其对"边缘端可装性"的影响并经批准，而非直接 commit。

### 9.3 绿色可复用清单（Apache-2.0 / MIT / BSD，可 fork/port/直接依赖）

- 感知：SAM 2（Apache-2.0，代码+权重）、GroundingDINO v1（Apache-2.0）、OpenCLIP（Apache-2.0，已依赖）、KISS-ICP（MIT）；
- 记忆参照：ConceptGraphs（代码 MIT）、HOV-SG（MIT）、Hydra（BSD-2）；
- 大脑：Cosmos-Reason（NVIDIA Open Model License，商业可用、允许衍生，已对接）、LeRobot（Apache-2.0）、openpi（Apache-2.0）、SmolVLA（Apache-2.0）、RoboBrain 2.0/2.5（Apache-2.0）、InternVLA/FluxVLA/WALL-OSS/RLDX-1（Apache/MIT）、傅利叶 N1（完全开源）。

> **fork/port 前必做：** Clio / 3DLLM-Mem / RoboMemory / Embodied-RAG 的确切许可证多为"待确认"，逐仓核 LICENSE 后方可引入（调研 7. 待调研空白）。
