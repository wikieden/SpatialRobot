---

This report is based on 8 dimensions of survey data that has been adversarially verified (confirmed / updated / uncertain / refuted), providing input for setting the vision and architecture of the SpatialRobot project. All numbers are handled by verdict: refuted ones are not adopted, updated ones use the revised value, and uncertain ones are explicitly flagged as "to be verified". The report also incorporates a careful reading of the actual code across this repository's three layers (tempomem / worldsense / mindloop) (key facts: the core uses the three Protocols `PerceptionAdapter` / `Verbalizer` / `Reasoner` as BYO seams; `Brain.ask()` produces, via `serialize(format="prompt")`, a token-efficient hierarchical scene graph carrying `#id` references that is fed to the Reasoner, which then closes the loop with `Answer(text, cited_node_ids)` back to locatable node ids; query routing is layered as relational → intent → semantic-vec/keyword).

## 1. Executive Summary

1. **Landscape assessment: China and the US present a mirrored division of labor — "software brain vs. hardware body" — but both are converging toward the middle.** The US leaders (NVIDIA, Google DeepMind, Physical Intelligence, Figure, Skild, Generalist) anchor on the software layer of foundation models / VLA / world models, with hardware mostly via partners; the Chinese leaders (Unitree, AgiBot, UBTech, Fourier, RobotEra, LimX, Galbot) lead on mass-produced bodies and shipment volume, with the brain layer being rapidly reinforced over the past year by open-source research institutes (BAAI RoboBrain, Shanghai AI Lab InternRobotics, Beijing Humanoid National-Local Center) and VLA startups (Spirit AI, X Square, Noematrix, Galbot). **Both sides lack an engineered, persistable, queryable structured spatial memory layer — which is precisely the scarce slot Chronotope fills.**

2. **The technical paradigm has clearly converged from "end-to-end VLA" to "hierarchical dual-system (S2 slow-reasoning VLM + S1 fast-execution policy)" as a 2024–2025 industrial de facto trend (note: in the research data, the item "PsiBot was first to propose the dual-system" was refuted, and the "de facto standard" phrasing is on weak evidence — it is better stated as "leading companies converged").** Figure Helix, π0.5/Hi Robot, NVIDIA GR00T N1, and Gemini Robotics-ER are all this structure. Chronotope's three layers map naturally onto it: the brain layer = S2, the controller (not included) = S1, **and the memory layer fills the "cross-frame persistent spatial state" that all of these systems commonly lack.**

3. **The World Model is a third pole complementary to — not competing with — spatial memory.** Cosmos 3, 1X World Model, Wayve GAIA-1, Covariant RFM-1, and X Square WUM do pixel-level imagination / synthetic data / forward prediction; Chronotope does structured, explicit, queryable 3D object-relation memory. The two combined (world model generates training data + scene graph provides a structured prior that shrinks the search space) is a valuable combination, not a substitution relationship.

4. **Spatial memory / 3D scene graphs are already a clear academic paradigm, and the mainstream academic technical choices align closely with Chronotope but are more engineered.** ConceptGraphs, Hydra/Clio, HOV-SG, Embodied-RAG, 3DLLM-Mem, and RoboMemory are all implementations of this paradigm; Chronotope's numpy-only core + sqlite-vec ANN + PerceptionAdapter protocol + `#id`-referenceable serialization is the differentiated path of turning this academic capability into an installable, embeddable, commercially usable engineering component.

5. **The most critical takeaway for us: Chronotope should not compete head-on with VLA / bodies / brain large models, but should be "the external spatial hippocampus that any S2 can mount."** Almost every competitor (π0.7's MEM, 1X mentioning memory context, FieldAI's mapless navigation, DYNA's on-the-job continual learning, Galbot's shelf state, BAAI RoboOS's "cross-robot spatial-memory sharing") in fact needs, but none of them has built, an independent, reusable, persistent spatial-memory layer.

6. **On licensing and reusability, our "numpy-only core + protocol seams" route is naturally suited to the open-source ecosystem.** The high-value open-source components that can be directly forked/ported (LeRobot, openpi, ConceptGraphs, Hydra, SAM 2, GroundingDINO, OpenCLIP, Cosmos-Reason, RoboBrain) are mostly Apache-2.0 / MIT / BSD; the traps to avoid are ORB-SLAM3 (GPLv3 contagion), AgiBot World / parts of RoboCasa datasets (CC BY-NC-SA non-commercial), and LLaMA-2-derived weights (the 700M MAU clause).

7. **Data and simulation infrastructure: the recommendation is "do not build large-scale collection or a general-purpose simulator in-house, maximize reuse."** OXE / DROID / RoboMIND / AgiBot World cover the pretraining corpus (note AgiBot World is a non-commercial license); Isaac Sim (Apache-2.0 core) / MuJoCo / Genesis / ManiSkill3 cover simulation; CALVIN / LIBERO / RLBench / SimplerEnv cover evaluation. The only thing we should build in-house is **an evaluation set targeting "spatial-memory query correctness"** (referencing Embodied-RAG's Embodied-Experiences and 3DMem-Bench) — this is an unoccupied blank.

8. **Risk note: funding and shipment numbers in this track are extremely prone to going stale and have muddled definitions.** Multiple claims of "world first / highest valuation / cumulative delivery" were flagged as uncertain or refuted during verification (e.g., Galbot's ¥9.3B funding was refuted, Skild $14B/$30M ARR is to be verified, Fourier's 10,000 units are mostly rehabilitation exoskeletons, and the Unitree vs. AgiBot "world first" definitional dispute). When setting the vision, anchor on **technical architecture and ecological niche**, not on these marketing numbers.

### 2.3 China-US Differences Commentary

- **Hardware vs. software division of labor**: US startups (PI, Skild, Generalist, Field AI, Covariant, Dyna) are largely **pure-software foundation-model companies**, explicitly aiming to "be the Android/brain supplier of the robot world," outsourcing hardware; the Chinese leaders are **leading in body mass-production** (Unitree/AgiBot/UBTech/Fourier lead globally in shipment volume and IPO progress), with the brain layer reinforced only in the past year by research institutes' open-sourcing (BAAI/Shanghai AI Lab/National-Local Center) and VLA startups (Spirit AI/X Square/Noematrix/Galbot).
- **Open-source strategy differences**: China's "national team + research institute" route open-sources **brain models and datasets at large scale** (RoboBrain, InternVLA, Huisi Kaiwu, AGIBOT WORLD, RoboMIND, FluxVLA, WALL-OSS, Spirit v1.5, RLDX-1), forming a second open-source supply line parallel to the US's "NVIDIA open weights + academia Apache/MIT." US closed-source startups (Figure/PI commercial version/Skild/Generalist) keep their strongest capabilities in private versions.
- **Data-flywheel anchor differences**: the US relies on human wearables (Generalist 500,000 hours), warehouse deployments (Covariant), teleoperation (PI/ALOHA); China relies on real business scenarios (Alibaba warehousing/delivery/retail, Galbot retail stores, UBTech/AgiBot automaker production lines).
- **Common blank**: both China and the US's S2/brain layers **default to having no persistent, queryable structured spatial memory** — this is Chronotope's neutral ecological niche (it can serve both sides' OpenAI-compatible Reasoners simultaneously).

## 3. Technical Architecture Paradigm Comparison

| Paradigm | Representative Works | Core Mechanism | Strengths | Weaknesses | Trend Tradeoffs |
|---|---|---|---|---|---|
| **End-to-end VLA** | RT-2, OpenVLA(7B), π0, MolmoAct 2, RDT-1B, GR-3, Spirit | Vision+language+action unified single network, one forward pass emits action tokens (discrete/diffusion/flow matching) | Simple, low-latency, no coordination overhead; OpenVLA 7B beats RT-2-X 55B by **16.5% on encoder selection (confirmed; "saves 70% GPU time" was updated to about 87.5%/8x)** | Hard to debug local failures, poor cross-platform generalization, decays with step count on long-horizon tasks, **no explicit scene memory / no cross-frame persistent state** | Still the SOTA baseline, but the monolithic route tops out on long-horizon tasks and is being absorbed by dual-system |
| **Hierarchical dual-system (S1+S2)** | Figure Helix, π0.5/Hi Robot, GR00T N1, Gemini Robotics-ER, Fast-in-Slow | S2 (7B VLM, 7-9Hz, planning) + S1 (80M policy, 200Hz, control), bridged by latent/NL sub-instructions/action chunks | Multi-timescale reasoning, good safety, easy long-horizon; **leading companies converged in 2024-25 (the "de facto standard" phrasing is on weak evidence; "PsiBot was first to propose" was refuted)** | Coordination latency, S1/S2 alignment difficulty, engineering complexity; **S2 still has no persistent spatial memory** | Industry mainstream. Fast-in-Slow eliminates coordination overhead via parameter sharing (RLBench 69% vs π0 55%); three-system adds a Critic to improve OOD |
| **World Model** | Cosmos 3, Genie 2/3, 1X WM, Wayve GAIA-1, Covariant RFM-1, X Square WUM, V-JEPA 2 | Video-generation model simulates environment dynamics, rollout/plan/generate synthetic data in imagination | Mitigates the data bottleneck, safe evaluation, policy improvement; **Cosmos 3 unified single-system confirmed ("30s prediction" to be verified)** | Action consistency, long-horizon error accumulation, large real-time inference cost, non-unified evaluation metrics | Rapidly evolving; positioned as a learned simulator / synthetic-data source, **not a replacement for the perception+memory layer** |
| **Spatial memory / 3D scene graph** | ConceptGraphs, Hydra/Clio, HOV-SG, Embodied-RAG, 3DLLM-Mem, RoboMemory, **Chronotope** | RGB-D → persistent queryable 3D object graph, injecting structured spatial context into the VLM/LLM planner | Solves the VLM's no-cross-frame-memory pain point; lightweight, queryable, referenceable; 3DLLM-Mem **32.1% vs baseline about 5% on hard tasks (confirmed)** | Mostly academic, few commercial products; dense vs. sparse representation not yet settled; depends on upstream perception quality | From sparse object graph → dense 3D patch, from static → dynamic; the trend is integration with dual-system's S2 |

**Tradeoff conclusion**: end-to-end VLA and dual-system are two generations of the "action generation" mainline; the world model is the "data/imagination" auxiliary pole; spatial memory is the "persistent state/memory" pole. **These three poles are orthogonally complementary** — Chronotope should clearly stand on the "spatial-memory pole," serving as the bolt-on memory for the dual-system S2 and the structured-prior provider for the world model, rather than building a fourth VLA. The repository code already naturally falls into this position: `serialize(format="prompt")` produces a hierarchical scene graph carrying `#id` → the Reasoner reasons → `Answer.cited_node_ids` refers back to locatable nodes — exactly the engineering implementation of the "VLM planner + structured spatial context" paradigm.

## 5. Data / Simulation / Evaluation Infrastructure

**General principle: maximize reuse, build in-house only on "spatial-memory evaluation."**

**Datasets (for perception/memory pretraining validation, not self-collected):**
- **OXE / RT-X** (CC BY 4.0, subsets retain original restrictions): 1M+ trajectories, 22 embodiments, the de facto standard for VLA pretraining; the limitation is that it is mostly short-horizon pick-and-place.
- **DROID** (open-source permissive license): 76k trajectories/564 scenes, **+22% in-distribution / +17% out-of-distribution compared to the next-best method (confirmed)**; multi-view RGB-D + camera calibration directly feeds perception.

**Simulators (do not build a general-purpose simulator in-house):**

**Evaluation (reuse general, build in-house the spatial-memory special):**
- Reuse **CALVIN** (MIT, language-conditioned long-horizon), **LIBERO** (MIT, lifelong-learning forward/backward transfer, directly corresponding to our decay/consolidate), **RLBench** (MIT, 100+ tasks), **SimplerEnv** (MIT/Apache, **strong sim-real correlation confirmed, but positioned as a "proxy" not a "replacement," main metric uses MMRV**).
- **In-house item**: referencing Embodied-RAG (Embodied-Experiences) and 3DLLM-Mem (3DMem-Bench), build an evaluation set for **"spatial-memory query correctness + cited_node_ids recall + cross-episode persistence + decay/forget correctness."** This is currently an unoccupied blank that directly proves our value proposition and should be built in-house as a priority.

## 6. Vision / Architecture Recommendations for SpatialRobot

### 6.1 The Differentiation Wedge: the Spatial Memory Layer Really Is a Scarce Slot

The evidence chain is clear: (1) end-to-end VLA and dual-system S2 **structurally lack persistent cross-frame spatial state** (OpenVLA/π0/Helix/GR00T/Gemini-ER are all single-frame or short-context); (2) the leading companies in fact need it — π0.7 only just added a history vision encoder (MEM), 1X explicitly says it "needs memory context to handle drift/partial observability," Field AI's mapless navigation has localization/replanning pain points, DYNA's on-the-job continual learning needs persistent environment knowledge, Galbot's shelf-state tracking, BAAI RoboOS writes "real-time cross-robot spatial-memory sharing" into its architecture; (3) academia has already formed the paradigm but **almost no one has turned it into an independent, installable, commercially usable, numpy-only engineering component** (ConceptGraphs/Hydra/Clio/Embodied-RAG/3DLLM-Mem/RoboMemory are all research code or heavy C++/ROS stacks). The repository's engineering choices (numpy-only core, sqlite-vec ANN, `.smem` single file, the three protocols `PerceptionAdapter`/`Verbalizer`/`Reasoner` as seams, `#id`-referenceable serialization, the fuse-before-persist invariant) happen to turn this academic capability into **an external hippocampus that can embed into any S2**. **Conclusion: the wedge holds, and it is a neutral ecological niche (both China and the US, any OpenAI-compatible Reasoner, can mount it).**

### 6.2 Relationship to Each Paradigm (Explicitly Stating What We Don't Do)

- **Don't do end-to-end VLA / don't do brain large models**: that is the red ocean of PI/Skild/Generalist/RoboBrain/Spirit AI/X Square, and we would surely lose going there.
- **Don't do bodies**: that is the capital-intensive track of Unitree/AgiBot/Fourier/LimX.
- **Do the memory layer of dual-system**: position Chronotope as "structured spatial memory + query service that any S2 (Cosmos-Reason / RoboBrain / Gemini-ER / π0.5) can call." `Brain.ask()` is already the prototype of this interface.
- **Be the structured-prior provider for the world model**: use the world model to generate synthetic RGB-D to expand the perception training set; use the `.smem` scene graph to provide object-position/relation priors for imagination rollout, shrinking the search space.

### 6.3 Phased Roadmap Recommendations

- **Phase 1 (foundation, 0–3 months)**: solidify the memory core and BYO seams. Land the first concrete `PerceptionAdapter` implementation (ConceptGraphs route: SAM 2 + GroundingDINO + OpenCLIP, all Apache/MIT, behind the `[perception]` extra); solidify the dual Reasoner backends Cosmos-Reason2 / RoboBrain; build the spatial-memory evaluation set in-house (the wedge of 6.1 must have numbers to support it).
- **Phase 2 (integration validation, 3–6 months)**: do an end-to-end demo on 1–2 open-source-friendly domestic bodies (Fourier N1 fully open-source, LimX FluxVLA(MIT), Galbot's retail-shelf scene is a textbook use case); integrate the LeRobot ecosystem (LeRobotDataset feeds perception, its 5 official VLAs as downstream S1); integrate one external S2 (RoboBrain RoboOS's "spatial-memory sharing" is the most fitting integration point).
- **Phase 3 (ecological-niche lock-in, 6–12 months)**: make Chronotope the "embodied-memory standard interface" — publish a stable serialization protocol (the `#id`-referenceable prompt format already exists), cross-episode/cross-robot persistence, the decay/consolidate lifecycle; aim to be adopted as the default memory layer by an open-source brain (RoboBrain / InternRobotics) or a body manufacturer. For commercial scenarios prefer **multi-shift/long-duration continuous operation** (UBTech Walker S2 7×24h, DYNA 24h, multi-shift warehousing) — in these scenarios persistent spatial memory is a hard requirement rather than a nice-to-have.

### 6.4 Licensing Traps and Pitfalls to Avoid

- **Licensing traps**: ORB-SLAM3 (**GPLv3 contagion**, do not link into the distribution package, use KISS-ICP/MIT for pose); AgiBot World / parts of the RoboCasa dataset (**CC BY-NC-SA non-commercial**, research-only); OpenVLA / any LLaMA-2-derived weights (**700M MAU clause**, prefer LLaMA-3.2/Qwen-series backbones); GR00T N1/N1.5 weights (**NVIDIA non-commercial license, commercial-use prohibited**, for commercial use N1.7 Apache-2.0 or Cosmos Open Model License).
- **Engineering pitfalls**: keep the core numpy-only contract (CLAUDE.md already mandates: adding a torch/LLM import to tempomem/ breaks the contract); the fuse-before-persist invariant (a new mutator must first `_flush_pending()`); keep tests network-free (use ScriptedReasoner / HashEncoder).
- **Strategic pitfalls**: do not let "shipment volume/valuation/world first" marketing numbers set the rhythm for the vision — multiple such claims were refuted/uncertain in this verification; anchor on the technical ecological niche.

**Gaps requiring further research:**

- **Whether next-generation S2 such as Cosmos 3 / RoboBrain 2.5 will internalize memory capability**, thereby compressing the space for an external memory layer (π0.7 has already begun internalizing MEM) — this is the wedge's biggest long-term risk and needs continuous monitoring.
